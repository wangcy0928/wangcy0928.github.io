Yangtze Berth Atlas

I built a scraper that collected every berth listed on a shipping-data platform along the Yangtze River from Chongqing to Shanghai. I then cleaned the data into a single table and made a map tool that switches between a nautical chart and satellite imagery, so each berth's type can be checked by eye. The hardest bug was markers that drifted hundreds of metres whenever the base map changed. The cause turned out to be China's GCJ-02 coordinate offset.

Correction is off. On this layer every marker is now drawn about 300–600 m away from its true position. This is the drift bug.

How it works

01 · Discover

Reverse-engineer the API

Captured the map app's XHR traffic and found the region and berth endpoints. With an authorised account, the request headers are derived from the session JWT, so only one credential needs to be configured.

02 · Locate

Find Yangtze ports

Queried six overlapping rectangles, since one big box timed out. Ports were then filtered by haversine distance (≤ 30 km) to a 70-point polyline of the main channel.

03 · Collect

Resumable scraping

Each port's berths are cached to their own file with atomic writes. Timeouts and expired tokens just mean re-running the command: only the missing ports get fetched.

04 · Deliver

Clean + export

1,828 berths × 95 raw fields go into one bilingual Excel workbook, with fill-rate stats per field and an option to drop the ~55 always-empty columns.

The drifting-marker bug

The berth coordinates and the nautical chart both use WGS-84, the raw GPS system. Satellite maps served inside China use GCJ-02, a system that by regulation shifts every point by a non-linear offset. Along the Yangtze that offset is about 300–600 m, and its size changes from place to place.

So the same latitude/longitude lands in a different spot on each base map. Switching layers made every marker jump.

Fix: store everything in WGS-84 as the single source of truth. When the active layer is GCJ-02, run each point through the published WGS-84 → GCJ-02 transform before drawing it. The transform is a polynomial plus sine terms, converted from metres to degrees with the Krasovsky ellipsoid. Re-project from the original coordinates every time, never from the previous output, so errors don't pile up.

Try it: switch to Satellite (China, GCJ-02), zoom in on a port, and untick Coordinate correction. Click any berth to see the size of the offset at that exact spot.
